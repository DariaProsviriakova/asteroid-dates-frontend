# Asteroid Dates Frontend — лабораторная №5

Гостевой SPA на **React, TypeScript, Vite и React-Bootstrap**. Предметная «услуга» — карточка даты сближения астероида с Землёй.

**Ветка:** `lab5-dates-react-spa`.

## Соответствие заданию

| Требование | Реализация |
| --- | --- |
| Три страницы | Плитка, лента, регистрация |
| Интерфейс гостя | Просмотр карточек, фильтрация и переходы; изменение карточек недоступно |
| Четыре пункта navbar | Лента, Добавление, Плитка, Вход |
| Только два доступны | Лента и Плитка; Добавление и Вход — настоящие disabled-кнопки без ссылок |
| Фильтр по теме | Ползунок максимального месяца сближения, 1–12 |
| React-Bootstrap | Карточки, формы, кнопки, navbar, загрузка и ошибки |
| Только mock-карточки | Единственный источник — `src/mocks/dates.ts`; бэкенд и браузерная БД не используются |
| Локальные медиа по умолчанию | Изображение и видео включены в `public/media` |
| Без Redux и Context | В коде приложения нет Redux, `createContext` и `useContext` |
| README | Ниже описаны страницы, поля, кнопки, props и все хуки |

Регистрация сохранена как третья страница по отдельному требованию пользователя и открывается ссылкой над плиткой. Она не включает вход или добавление. Маршруты `/login` и `/dates/add` перенаправляют в плитку, поэтому отключённые разделы нельзя открыть прямым адресом.

## Визуал

Сохранено оформление [ЛР2 старого репозитория](https://github.com/DariaProsviriakova/web_backend_asteroids/tree/lab2-asteroids-postgresql): узкая область приложения до 498 px, тёмный внешний фон, белая плитка в два столбца, прежние цвета, изображения, размеры, крестики и нижняя панель.

[`src/backend.css`](src/backend.css) — неизменённая копия CSS ЛР2. [`src/styles.css`](src/styles.css) содержит совместимость с Bootstrap, четвёртый пункт navbar, отключённые состояния и форму регистрации. Полоска активной доступной вкладки имеет прежние размеры 48 × 3 px и расположена под текстом. Крестики остаются 32 × 32 px, но удаление гостю недоступно.

## Запуск

Нужны Node.js 22.12+ (рекомендуется 24) и npm.

```bash
git clone https://github.com/DariaProsviriakova/asteroid-dates-frontend.git
cd asteroid-dates-frontend
git switch lab5-dates-react-spa
npm ci
npm run dev
```

Откройте **http://127.0.0.1:5173/dates**. Для демонстрации достаточно Vite: данные карточек предоставляет MSW из mock-коллекции проекта.

```bash
npm run build
npm run preview
```

Собранное приложение: **http://127.0.0.1:4173**. MSW работает и в разработке, и в сборке. Для Service Worker нужен localhost/127.0.0.1 или HTTPS; `file://` не поддерживается. На статическом хостинге нужен fallback маршрутов к `index.html`.

## Страницы, кнопки и поля

### 1. Плитка — `/dates`

Заголовок **«ВЫБОР ДАТЫ»**, фильтр и шесть карточек. На каждой карточке — изображение, обозначение астероида, дата с годом, расстояние в а.е. с тремя знаками после запятой и количество лайков.

| Элемент | Поведение |
| --- | --- |
| «Фильтр по месяцу: до N» | Ползунок 1–12 выбирает максимальный месяц; условие: месяц карточки ≤ N |
| «Показать» | Применяет выбранное значение, обновляет `maxMonth` в URL и выполняет новый mock GET |
| Изображение / название | Открывает выбранную карточку в ленте |
| «Сбросить фильтр» | При пустой выдаче возвращает весь список |
| «Регистрация» | Открывает третью страницу |
| Сердце и число | Только отображение количества лайков |
| «×» | Прежний вид сохранён, кнопка disabled: гостевое удаление не предусмотрено |

До нажатия «Показать» ползунок меняет только черновик поля. Примеры: `/dates?maxMonth=5` — две майские карточки, `/dates?maxMonth=1` — пустой результат. Фильтр сохраняется при обновлении и восстанавливается через историю браузера.

### 2. Лента — `/dates/feed`, `/dates/feed/:id`

Прежнее видео без звука, обозначение астероида, заголовок **«МИНИМАЛЬНОЕ РАССТОЯНИЕ ДО ЗЕМЛИ»**, описание и правая колонка с датой, расстоянием, сердцем и счётчиком.

| Элемент | Поведение |
| --- | --- |
| «Еще↓» / «Меньше↑» | Раскрывает и сворачивает описание |
| Круглая кнопка «→» | Следующая дата; после последней — первая |
| Сердце и число | Только просмотр; лайки гостем не изменяются |
| «Плитка» в navbar | Открывает список дат |

`/dates/feed/5` открывает конкретную дату. Старые ссылки `/feed?id=5` и `/dates/5` перенаправляются в ленту. Неизвестный ID или путь показывает 404; навигация остаётся доступной.

### 3. Регистрация — `/register`

Новая форма в прежних стилях приложения.

| Поле / кнопка | Назначение |
| --- | --- |
| Имя | Обязательное имя, до 80 символов |
| Email | Обязательный корректный email, до 120 символов |
| Пароль | Обязательный скрытый ввод, проверка длины 8–128 |
| Повторите пароль | Проверка совпадения; это поле не передаётся в запросе |
| «Зарегистрироваться» | Проверяет поля и отправляет mock POST |
| «Лента» / «Плитка» в navbar | Переход к просмотру услуг |

На время запроса поля и кнопка отключаются. Ошибки полей и занятого email выводятся у формы. Успех показывает результат регистрации и имя.

Регистрация моделируется в памяти страницы. Пароли не сохраняются и не возвращаются в ответе. Вход, авторизация, сессии и дополнительные права не реализуются в ЛР5; после регистрации navbar по-прежнему имеет только два доступных пункта.

## Нижний navbar

| Пункт | Доступность |
| --- | --- |
| Лента | Доступен, `/dates/feed` |
| Добавление | Отключён |
| Плитка | Доступен, `/dates` |
| Вход | Отключён |

Отключение сделано намеренно по условию ЛР5. Эти пункты не имеют `href`, не выполняют запросов и не открывают формы. Активная полоска отображается у текущего доступного раздела.

## Mock и вкладка Network

Единственная коллекция карточек — [`src/mocks/dates.ts`](src/mocks/dates.ts). Начальные данные не меняются, не подменяются данными IndexedDB и не загружаются из бэкенда.

Путь данных: **страница → useDates → fetch → MSW → mock-коллекция → JSON → React**.

| Запрос | Результат |
| --- | --- |
| `GET /api/dates` | Все mock-карточки |
| `GET /api/dates?maxMonth=5` | Карточки с месяцем ≤ 5 |
| `GET /api/dates/feed` | Первая карточка |
| `GET /api/dates/feed?id=5` | Конкретная карточка |
| `GET /api/dates/feed?id=5&next=true` | Следующая карточка |
| `POST /api/users/register` | Учебный результат регистрации; 201 / 400 / 409 |

Откройте DevTools → **Network → Fetch/XHR**. Обновите плитку или ленту, измените фильтр либо отправьте регистрацию. В **Response** видны mock-объекты; в заголовках — **`X-Data-Source: mock`**, источник ответа — Service Worker.

Обработчики находятся в [`src/mocks/handlers.ts`](src/mocks/handlers.ts). `main.tsx` дожидается старта MSW перед монтированием React. GET-запросы отменяются при смене страницы/параметров, поэтому устаревшие ответы не перезаписывают новые данные. В StrictMode начальный запрос при разработке может быть отменён и повторён.

## Изображение и видео по умолчанию

Оба файла находятся в проекте:

- [`public/media/default-date.png`](public/media/default-date.png);
- [`public/media/default-date.mp4`](public/media/default-date.mp4).

[`resolveMedia`](src/lib/media.ts) обрабатывает `null`, пустую строку и пробелы. [`DateImage` и `DateVideo`](src/components/DateMedia.tsx) подставляют локальные файлы, а также используют их при ошибке загрузки указанного URL.

Для показа: у **2026 JD4, ID 5** оба поля пустые. На плитке отображается изображение по умолчанию, на **`/dates/feed/5`** — видео по умолчанию. У **2026 HF4, ID 6** видео задано пустой строкой. В DOM есть `data-default="true"`, в Network — загрузка `default-date.*`. Внешний S3 для показа не нужен.

## Компоненты и props

| Компонент | Props |
| --- | --- |
| `DatesFilter` | `filters: { maxMonth }` — применённое значение; `onApply(filters)` — callback родителю |
| `DateCard` | `date: AsteroidDate` — одна карточка |
| `DateImage` | `src`, `alt`, необязательные `className`, `loading` |
| `DateVideo` | `src`, `poster`, `designation`, `ambient` |
| `ErrorState` | `message`, `onRetry` |

`DatesFilter` хранит черновик месяца через `useState`. При submit вызывает `onApply`; родитель обновляет URL, хук получает новый путь запроса, MSW фильтрует коллекцию. Дочерний компонент не изменяет props. `useEffect` синхронизирует поле с URL при переходах по истории.

Используются React-Bootstrap `Card`, `Card.Body`, `Form`, `Form.Group`, `Form.Label`, `Form.Control`, `Form.Control.Feedback`, `Button`, `Navbar`, `Nav.Link`, `Spinner`, `Alert`. Bootstrap CSS импортирован перед исходными стилями ЛР2.

## Все используемые хуки

| Хук | Назначение |
| --- | --- |
| `useState` | Данные, загрузка, ошибка и повтор в `useDates`; месяц в фильтре; ошибки медиа; поля и результат регистрации |
| `useEffect` | GET и его отмена; отправка регистрации и отмена; синхронизация фильтра; сброс ошибки медиа; заголовок вкладки; прокрутка при переходе |
| `useDates<T>` | Собственный хук получения данных и состояний запроса |
| `useDocumentTitle` | Собственный хук заголовка вкладки |
| `useSearchParams` | React Router: фильтр и параметры ленты |
| `useParams` | React Router: ID карточки и совместимость старого адреса |
| `useLocation` | React Router: адрес при перенаправлении и прокрутка |

Других хуков в приложении нет. Redux, собственные Context-провайдеры и `useContext` не используются.

## Проверки

```bash
npm test
npm run build
npx playwright install chromium --only-shell
npm run test:e2e
```

Модульные тесты проверяют фильтрацию и выбор медиа. Браузерные сценарии проверяют production-сборку на компьютере и телефоне: оформление, ровно два доступных пункта navbar, блокировку прямых адресов, mock-ответы, фильтр/историю, fallback медиа, ленту, регистрацию без лишних текстов, неизменяемость карточек гостем и 404.

GitHub Actions запускает те же проверки при push. Отчёт и РПЗ не создаются.
