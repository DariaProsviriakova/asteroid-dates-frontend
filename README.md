# Asteroid Dates Frontend — лабораторная №5

React + TypeScript + Vite + React-Bootstrap. Отдельный фронтенд проекта дат сближения астероидов с Землёй.

**Ветка:** `codex/lab5-dates-react-spa`.

## Визуал ЛР2

Оформление перенесено из [ветки ЛР2 старого репозитория](https://github.com/DariaProsviriakova/web_backend_asteroids/tree/lab2-asteroids-postgresql), коммит `69deb0759dddfa56d777f09a4aca05564271f293`.

[`src/backend.css`](src/backend.css) — неизменённая копия `public/styles/app.css` ЛР2. Сохранены шаблоны плитки, ленты и двух шагов добавления: узкая область до 498 px, тёмный внешний фон, белая плитка в два столбца, синий текст, прежние изображения, круглые крестики 32 × 32 px, шкала месяца, кнопки, отступы и полоска активной вкладки 48 × 3 px.

В [`src/styles.css`](src/styles.css) находятся настройки совместимости с Bootstrap, четвёртый пункт navbar и новые формы. Полоска остаётся **под текстом**, на расстоянии 16 px от нижней границы. На компьютере область приложения сохраняет размеры 498 × 1080 px, на телефоне занимает экран; длинные формы и плитка прокручиваются внутри.

## Запуск

Нужны Node.js 22.12+ (рекомендуется 24) и npm.

```bash
git clone https://github.com/DariaProsviriakova/asteroid-dates-frontend.git
cd asteroid-dates-frontend
git switch codex/lab5-dates-react-spa
npm ci
npm run dev
```

Откройте **http://127.0.0.1:5173/dates**. Бэкенд, Docker, PostgreSQL, Redis и MinIO запускать не нужно.

```bash
npm run build
npm run preview
```

Сборка: **http://127.0.0.1:4173**. MSW включён и в разработке, и в сборке. Service Worker требует localhost/127.0.0.1 или HTTPS. На статическом хостинге нужен fallback маршрутов к `index.html`.

## Доступность действий

По дополнительному требованию пользователя **все четыре вкладки включены**: «Лента», «Добавление», «Плитка», «Вход». Это расширяет исходный гостевой минимум ЛР5 с двумя доступными пунктами.

Добавление, публикация, лайки, удаление, регистрация, вход и выход работают **с учебными mock-данными**. Удаление и добавление доступны и без входа, как в интерфейсе ЛР2. Настоящий сервер и реальные аккаунты не затрагиваются.

Демонстрационный вход:

```text
Email: daria@example.com
Пароль: AsteroidLab4!
```

Можно зарегистрировать нового наблюдателя и войти с его данными. Учебное состояние сохраняется в IndexedDB этого браузера: карточки, черновик, загруженные файлы, профили и текущий вход переживают обновление страницы. При запрете браузерного хранилища приложение работает в памяти страницы.

## Страницы и кнопки

### Плитка — `/dates`

- Заголовок **«ВЫБОР ДАТЫ»**, прежний ползунок месяца с отметками 1–12.
- **«Фильтр по месяцу: до N»** выбирает верхнюю границу: месяц карточки ≤ N.
- **«Показать»** применяет черновик ползунка, меняет `maxMonth` в URL и загружает отфильтрованную коллекцию.
- Изображение и название открывают выбранную дату **в ленте**, как в ЛР2.
- Карточка содержит название, дату с годом, расстояние в а.е. с тремя знаками после запятой и количество лайков.
- **«×»** удаляет карточку из учебной коллекции. Кнопка имеет исходный вид ЛР2.
- Сердце ставит и снимает лайк; состояние совпадает в плитке и ленте.
- **«Регистрация»** открывает форму нового наблюдателя.
- При пустом результате есть сообщение и сброс фильтра.

Примеры: `/dates?maxMonth=5` — две майские даты; `/dates?maxMonth=1` — пустой список. Фильтр восстанавливается после обновления и при переходах «Назад»/«Вперёд».

### Лента — `/dates/feed`, `/dates/feed/:id`

Фоновое видео без звука, обозначение астероида, прежний заголовок **«МИНИМАЛЬНОЕ РАССТОЯНИЕ ДО ЗЕМЛИ»**, описание, правая колонка с датой, расстоянием, сердцем и счётчиком.

- **«Еще↓» / «Меньше↑»** раскрывает и сворачивает описание.
- **«→»** показывает следующую дату; после последней возвращает первую.
- Сердце ставит и снимает лайк.
- Navbar открывает остальные разделы.

Адрес `/dates/feed/5` открывает конкретную дату. Адреса первой React-версии `/feed?id=5` и `/dates/5` также поддерживаются. Неизвестный ID или путь показывают 404 со ссылкой **«К выбору даты»**.

### Добавление — `/dates/add`

Повторяет два шага формы ЛР2.

| Шаг | Поля и действия |
| --- | --- |
| 1 | «Фото объекта», «Видео объекта», «Название астероида», «Далее» |
| 2 | Сохранённые медиа, название, «Описание», «Месяц сближения», «День сближения», «Опубликовать» |

Изображение и видео необязательны: при отсутствии используются локальные файлы по умолчанию. При выборе файла показывается предпросмотр. Допустимы изображения до 10 МБ и видео до 30 МБ. Название — до 120 символов, описание — до 700. Проверяется существование даты: например, 31 февраля опубликовать нельзя.

**«Далее»** сохраняет черновик и файлы. **«Изменить фото и название»** возвращает на первый шаг. **«Опубликовать»** добавляет дату в плитку и открывает её в ленте. Черновик и медиа доступны после обновления страницы.

### Вход и аккаунт — `/login`

Email и пароль, кнопка **«Войти»**, ссылка **«Зарегистрироваться»** и демонстрационные данные входа. Неверные данные показывают ошибку. После входа видны имя, email, ссылка **«Добавить дату»** и кнопка **«Выйти»**. Вход сохраняется после обновления; выход завершает учебную сессию.

### Регистрация — `/register`

Имя 1–80 символов, email до 120, пароль 8–128 символов, повтор пароля. **«Зарегистрироваться»** проверяет поля и отправляет запрос. Повтор пароля на сервер не передаётся. Ошибка занятого email выводится в форме; после успеха есть ссылка **«Войти»** с уже заполненным email.

Пароли не хранятся открытым текстом и не возвращаются в ответах. Для учебных профилей используется PBKDF2 с индивидуальной солью. Это локальная демонстрация, а не production-аутентификация.

## Mock и Network

Начальные карточки находятся только в [`src/mocks/dates.ts`](src/mocks/dates.ts). Mock-сервис изменяет их локальную копию. Страницы не импортируют коллекцию напрямую.

Путь данных: **страница → хук/API-клиент → fetch → MSW → учебное хранилище → JSON → React**.

| Запрос | Назначение |
| --- | --- |
| `GET /api/dates?maxMonth=5` | Плитка и фильтр |
| `GET /api/dates/feed?id=5&next=true` | Текущая/следующая дата ленты |
| `GET /api/dates/draft` | Сохранённый черновик |
| `POST /api/dates` | Создание/обновление черновика, multipart с файлами |
| `PUT /api/dates/publish` | Публикация |
| `DELETE /api/dates/:id` | Удаление |
| `POST /api/dates/:id/like` | Установка/снятие лайка |
| `POST /api/users/register` | Регистрация |
| `POST /api/users/auth` | Вход |
| `POST /api/users/logout` | Выход |
| `GET /api/users/session` | Восстановление учебного входа после обновления |
| `GET /demo-media/:key` | Медиа, загруженные в учебную коллекцию |

Откройте DevTools → **Network → Fetch/XHR**, обновите страницу или выполните действие. В Response видны данные, в заголовках — **`X-Data-Source: mock`**, источник ответа — Service Worker.

Обработчики: [`src/mocks/handlers.ts`](src/mocks/handlers.ts). Учебное состояние: [`src/mocks/store.ts`](src/mocks/store.ts). `main.tsx` запускает MSW перед монтированием React. Неизвестные API-запросы не уходят в настоящий бэкенд.

## Медиа по умолчанию

В проект включены [`public/media/default-date.png`](public/media/default-date.png) и [`public/media/default-date.mp4`](public/media/default-date.mp4).

[`resolveMedia`](src/lib/media.ts) подставляет файл при `null`, пустой строке или пробелах. [`DateImage` и `DateVideo`](src/components/DateMedia.tsx) переключаются на локальное медиа и при ошибке загрузки.

У **2026 JD4, ID 5** оба поля равны `null`: изображение по умолчанию видно в плитке, видео — на **`/dates/feed/5`**. У **2026 HF4, ID 6** видео — пустая строка. В DOM есть `data-default="true"`; Network показывает `default-date.*`.

## Компоненты и props

| Компонент | Props |
| --- | --- |
| `DatesFilter` | `filters: { maxMonth }`, callback `onApply(filters)` |
| `DateCard` | `date`, `pending`, callbacks `onDelete(date)` и `onLike(date)` |
| `DateImage` | `src`, `alt`, необязательные `className`, `loading` |
| `DateVideo` | `src`, `poster`, `designation`, `ambient` |
| `ErrorState` | `message`, `onRetry` |

Фильтр хранит черновик месяца в локальном состоянии. Submit передаёт его родителю через prop; родитель обновляет URL, хук загружает результат. Props дочерним компонентом не изменяются.

React-Bootstrap используется для карточек, форм, основных кнопок, navbar, загрузки и ошибок. Крестик, сердце и стрелка используют исходную разметку и CSS ЛР2, чтобы Bootstrap не менял их вид.

## Все хуки

| Хук | Где используется |
| --- | --- |
| `useState` | Данные, загрузка, ошибки, поля форм, черновики, состояние медиа |
| `useEffect` | Запросы/отмена, синхронизация фильтра, заголовок вкладки, прокрутка, предпросмотр файлов |
| `useRef` | Контроллер отмены в `useRequest`; прокрутка формы добавления к началу |
| `useDates<T>` | GET, загрузка, ошибка, повтор и обновление данных после действий |
| `useRequest` | Отправка изменений, состояние ожидания и ошибки, отмена при уходе |
| `useMediaPreview` | Создание и очистка временных URL для выбранных файлов |
| `useDocumentTitle` | Заголовок вкладки |
| `useSearchParams` | Фильтр, параметры ленты, email после регистрации |
| `useParams` | ID даты в ленте |
| `useLocation` | Активная вкладка, совместимость адресов, прокрутка при переходе |
| `useNavigate` | Переход к опубликованной дате |

Redux, `createContext` и `useContext` в приложении не используются.

## Проверки

```bash
npm test
npm run build
npx playwright install chromium --only-shell
npm run test:e2e
```

Playwright проверяет production-сборку на компьютере и телефоне: исходные цвета/геометрию, все вкладки и полоски, крестики и удаление, фильтр и историю, медиа по умолчанию, лайки, ленту, регистрацию/вход/выход, двухшаговое добавление, проверку даты, загрузку файлов и сохранение после обновления.

GitHub Actions запускает эти проверки при push. Отчёт и РПЗ не создаются.
