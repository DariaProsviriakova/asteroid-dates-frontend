# Asteroid Dates Frontend — лабораторная №5

Гостевой SPA-каталог дат сближения астероидов с Землёй: **React + TypeScript + Vite + React-Bootstrap**. Предметная «услуга» — карточка даты сближения. Сохранены названия и поля предметной области лабораторных №1–4.

Ветка лабораторной: **`codex/lab5-dates-react-spa`**.

Данные — только локальная mock-коллекция. Реальные `fetch`-запросы перехватывает **Mock Service Worker (MSW)**; сервер, PostgreSQL, Redis и MinIO для ЛР5 не требуются. Redux и пользовательский React Context не используются. React Router отвечает за маршруты и историю браузера.

## Запуск

Нужен Node.js **22.12+**; рекомендуемая версия — **24 LTS**, идущая с npm.

```bash
git clone https://github.com/DariaProsviriakova/asteroid-dates-frontend.git
cd asteroid-dates-frontend
git switch codex/lab5-dates-react-spa
npm ci
npm run dev
```

Откройте **http://127.0.0.1:5173**. Корневой URL перенаправляет на `/dates`.

Service Worker работает через `localhost`/`127.0.0.1` или HTTPS. Открытие `index.html` через `file://` не поддерживается. Все изображения, видео, стили и шрифты локальные; после установки зависимостей приложение не требует доступа к внешним API.

Для проверки сборки:

```bash
npm run build
npm run preview
```

Сборка доступна по **http://127.0.0.1:4173**. MSW включён и в `dev`, и в собранном приложении. На стороннем статическом хостинге необходим fallback неизвестных маршрутов к `index.html`, чтобы обновление `/dates/5` открывало SPA.

## Три страницы приложения

### 1. Плитка — `/dates`

Каталог из шести карточек. На каждой — изображение, название астероида, дата сближения, расстояние в астрономических единицах и количество лайков. Изображение, название и ссылка **«Подробнее»** открывают страницу отдельной даты.

| Поле / кнопка | Поведение |
| --- | --- |
| «Название астероида» | Поиск подстроки в названии, без учёта регистра; максимум 120 символов |
| «Сближения до месяца» | Ползунок 1–12; включаются все даты с месяцем **≤ выбранного**, как в ЛР1–4 |
| «Порядок» | Сортировка по дате, минимальному расстоянию или названию |
| «Показать» / Enter | Применяет все поля, меняет query-параметры URL и загружает отфильтрованную mock-коллекцию |
| «Сбросить» | Возвращает весь каталог, декабрь и сортировку по дате; очищает URL |
| «Сбросить фильтры» | Та же операция при пустом результате |

Примеры: `/dates?maxMonth=5` — две майские даты; `/dates?q=kr&maxMonth=6` — `2026 KR`; `/dates?sort=distance` — сначала `2026 KL2`; `/dates?maxMonth=1` — пустой результат. Фильтры сохраняются при обновлении страницы и восстанавливаются кнопками браузера «Назад» / «Вперёд».

### 2. Лента — `/feed`

Одна карточка с фоновым видео, обозначением астероида, описанием, датой, расстоянием и числом лайков. Фоновое видео запускается без звука, повторяется и воспроизводится внутри страницы на мобильных устройствах.

| Кнопка / ссылка | Поведение |
| --- | --- |
| «Следующая дата» | Показывает следующую запись; после последней возвращает первую |
| «Подробнее о дате» | Открывает подробную карточку текущего астероида |
| «Все даты» | Открывает плитку |

`/feed?id=5` открывает конкретную дату. Для перехода вперёд отправляется `GET /api/dates/feed?id=5&next=true`.

### 3. Подробности даты — `/dates/:id`

Название астероида, опубликованный статус, полное описание, дата, расстояние в а.е. и километрах, число лайков. Эта страница открывается из двух основных разделов; отдельного пятого пункта navbar нет.

| Кнопка / ссылка | Поведение |
| --- | --- |
| «Изображение» | Показывает изображение карточки |
| «Видео» | Переключает область медиа на видео с управлением воспроизведением, звуком и полноэкранным режимом |
| «Смотреть в ленте» | Открывает ленту именно на этой дате |
| «Даты сближений» в навигационной цепочке | Возвращает в плитку |

Несуществующий ID и неизвестный путь показывают состояние **404** со ссылкой в каталог. На всех страницах предусмотрены загрузка и ошибка с кнопкой **«Повторить»**. Лайки доступны гостю только для просмотра.

## Нижняя навигация

Постоянная панель **React-Bootstrap Navbar + Nav** содержит ровно четыре пункта:

| Пункт | Доступность гостю |
| --- | --- |
| Лента | Доступен, `/feed` |
| Добавление | `disabled`, без перехода |
| Плитка | Доступен, `/dates` |
| Вход | `disabled`, без перехода |

Активный раздел выделен; в подробностях активна плитка. Переключение страниц выполняется React Router без полной перезагрузки документа. Макет адаптирован под телефон, планшет и компьютер; navbar не закрывает содержимое.

## Mock и вкладка Network

Единственный источник карточек — [`src/mocks/dates.ts`](src/mocks/dates.ts). В коллекции шесть типизированных объектов `AsteroidDate`. Поля `designation`, `approachMonth`, `approachDay`, `minimumDistanceAu`, `imageUrl`, `videoUrl` и остальные публичные поля соответствуют модели ЛР4.

Путь данных: **компонент → `useDates` → `fetch` → MSW → mock-коллекция → JSON `{ data: ... }`**. Компоненты страниц не импортируют коллекцию напрямую. Обработчики находятся в [`src/mocks/handlers.ts`](src/mocks/handlers.ts), Service Worker — в `public/mockServiceWorker.js`. `main.tsx` сначала дожидается запуска MSW, затем монтирует приложение.

| Запрос | Ответ mock-сервиса |
| --- | --- |
| `GET /api/dates` | Массив опубликованных карточек |
| `GET /api/dates?maxMonth=5&q=kj&sort=date` | Фильтрация и сортировка коллекции |
| `GET /api/dates/feed` | Первая карточка ленты |
| `GET /api/dates/feed?id=2` | Конкретная карточка ленты |
| `GET /api/dates/feed?id=2&next=true` | Следующая карточка с циклическим переходом |

Страница подробностей получает `GET /api/dates` и находит нужный ID в результате. Это позволяет не придумывать дополнительный endpoint, которого нет в ЛР4. Параметры `q` и `sort` реализованы только в mock-сервисе ЛР5; реальный бэкенд пока поддерживает фильтр `maxMonth`. Автоматического переключения на бэкенд нет — карточки в этой лабораторной всегда берутся из mock.

Для показа откройте DevTools → **Network → Fetch/XHR**, обновите страницу и выберите запрос `/api/dates` или `/api/dates/feed`. В **Response** видны mock-объекты, в заголовках — **`X-Data-Source: mock`**, в источнике ответа — Service Worker. На плитке измените месяц и нажмите «Показать», чтобы увидеть параметры запроса. На ленте нажмите «Следующая дата». В подробностях также виден запрос коллекции. В React StrictMode при разработке первый запрос может быть отменён: это проверка очистки эффекта; повторный завершается успешно.

## Изображение и видео по умолчанию

Оба файла входят в репозиторий:

- [`public/media/default-date.png`](public/media/default-date.png);
- [`public/media/default-date.mp4`](public/media/default-date.mp4).

[`resolveMedia`](src/lib/media.ts) обрабатывает `null`, пустую строку и строку из пробелов. [`DateImage` и `DateVideo`](src/components/DateMedia.tsx) подставляют соответствующий локальный URL; изображение используется также как `poster` видео. Если указанный автором URL не загрузился, `onError` переключает компонент на локальный файл. Если недоступно даже видео по умолчанию, показывается изображение с сообщением.

Для демонстрации откройте **`/dates/5`** (`2026 JD4`): в mock у записи `imageUrl: null` и `videoUrl: null`. Сначала видны изображение и пояснение по умолчанию, после нажатия **«Видео»** — локальный ролик. На `/dates/6` дополнительно проверяется `videoUrl: ''`. На плитке у JD4 также используется изображение по умолчанию, а в `/feed?id=5` — видео по умолчанию. В DOM есть атрибут **`data-default="true"`** для проверки.

Медиа перенесены из предыдущего проекта Asteroid Dates и хранятся в `public/media`; обращений к S3/MinIO нет.

## Компоненты и props

| Компонент | Передаваемые props и ответственность |
| --- | --- |
| `DatesFilter` | `filters: DatesFilters` — применённые условия от `DatesPage`; `onApply(filters)` — callback, который родитель использует для обновления URL |
| `DateCard` | `date: AsteroidDate` — одна карточка; `index: number` — её номер в текущей выдаче |
| `DateImage` | `src`, `alt`, необязательные `className` и `loading`; выбор и отображение изображения |
| `DateVideo` | `src`, `poster`, `designation`, необязательный `ambient`; фоновое или управляемое видео |
| `ErrorState` | `message` и `onRetry`; текст ошибки и повторная загрузка |
| `Icon` | `name` и необязательный `size`; локальная SVG-иконка |

`DatesFilter` хранит черновик полей локально. Изменение ползунка ещё не меняет список; submit передаёт значения через `onApply`. Родитель меняет URL, `useDates` получает новый путь запроса, MSW фильтрует коллекцию и React перерисовывает карточки. Props не изменяются дочерним компонентом. При возврате по истории `useEffect` синхронизирует черновик полей с применёнными условиями из URL.

Используются React-Bootstrap `Container`, `Row`, `Col`, `Card`, `Form`, `Button`, `ButtonGroup`, `Badge`, `Navbar`, `Nav`, `Spinner`, `Alert`. Bootstrap CSS импортирован из установленного пакета.

## Все используемые хуки

| Хук | Место и назначение |
| --- | --- |
| `useState` | `DatesFilter`: черновик поиска, месяца и порядка; `DateDetailsPage`: выбранное медиа; `DateMedia`: состояние ошибки медиа; `useDates`: данные, загрузка, ошибка и счётчик повторов |
| `useEffect` | `useDates`: запрос при изменении пути или счётчика, очистка через `AbortController`; `DatesFilter`: синхронизация формы с URL; `DateMedia`: сброс ошибки при смене URL; `useDocumentTitle`: заголовок вкладки; `App`: прокрутка вверх при смене страницы |
| `useDates<T>` | Собственный хук загрузки, состояний и повторного запроса; устаревший/отменённый запрос не перезапишет новую выдачу |
| `useDocumentTitle` | Собственный хук заголовка текущей страницы |
| `useSearchParams` | React Router: чтение и запись фильтров плитки и параметров ленты в URL |
| `useParams` | React Router: ID на странице подробностей |
| `useLocation` | React Router: подсветка плитки в подробностях и прокрутка при переходе |

Других хуков в коде приложения нет. Общего хранилища, Redux, `createContext` и `useContext` в приложении нет.

## Структура

```text
src/
  api/dates.ts             # HTTP-клиент
  components/              # navbar, фильтр, карточка, медиа, состояния
  hooks/                   # useDates, useDocumentTitle
  lib/                     # форматирование, фильтрация, fallback медиа
  mocks/                   # коллекция, HTTP-обработчики, запуск MSW
  pages/                   # плитка, лента, подробности, состояние 404
  types/date.ts            # модель и типы фильтров
  App.tsx                  # маршруты и общий каркас
  main.tsx                 # MSW → монтирование React
  styles.css               # адаптивный интерфейс
public/media/              # все изображения и видео, включая fallback
tests/dates.spec.ts        # сценарии Chromium: компьютер и телефон
```

## Проверки

```bash
npm test
npm run build
npx playwright install chromium --only-shell
npm run test:e2e
```

Модульные тесты проверяют границы месяца, поиск, сортировку, сохранение фильтров в URL и выбор локальных медиа. Браузерные сценарии запускаются на **production-сборке** с двумя размерами экрана: три страницы, ответы MSW, два доступных пункта navbar, фильтры, пустая выдача, fallback изображения/видео, циклическая лента и 404. Для изменения логики mock после обновления MSW можно заново выполнить `npm run mocks:init`.

GitHub Actions запускает эти же проверки при push и pull request. Отчёт, РПЗ и расчёт аппаратных требований в этот репозиторий не входят.
